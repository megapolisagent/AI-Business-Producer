# AI Business Producer

Разбирает ваш бизнес — с нуля или уже существующий — до конкретной функциональной структуры: кто нужен уже сейчас, кто появится позже, и почему именно так, а не «вот вам общий шаблон оргструктуры».

Что это не заменяет: юриста (регистрация компании, форма собственности), бухгалтера, живых консультантов — этим агент не занимается вообще, см. «Чего агент никогда не делает» ниже.

## Как этим пользоваться

Пример запроса: «Разбери мой бизнес — [пара предложений: что это, для кого, на какой стадии]». Агент задаст 3-4 уточняющих вопроса (кто клиент, в чём отличие, что уже есть, что считать первым успехом) — не сразу выдаст структуру, если ответов ещё нет.

Другой пример: «Проверь, насколько реалистична моя идея [X] — есть ли кто-то, кто уже так делал» — агент отправляет узкий запрос агенту-исследователю и возвращает разбор с источниками, не собственное мнение.

## Режимы

| Режим | Что делает |
|---|---|
| Разбор с нуля | Идея, ещё не реализована — teardown с самого начала |
| Разбор существующего бизнеса | Уже что-то работает — teardown с поправкой на то, что уже есть |
| Координация специалиста | Структура уже понятна, нужен один узкий кусок внешней проверки |

Что не меняется ни в одном режиме: решение всегда за вами, агент предлагает — не решает; факт и предположение всегда разделены явно.

## Механизмы доверия

- **Предположение не выдаётся за факт.** В каждом разборе явно видно, что подтверждено внешней практикой (с источником), а что — предположение агента, которое можно оспорить.
- **Внешняя проверка, не собственная догадка.** Для крупных решений агент не сочиняет «как это обычно бывает в недвижимости» — отправляет узкий вопрос агенту-исследователю с заранее зафиксированным критерием ответа, и показывает вам, что реально нашлось, включая честное «не найдено», если ничего не нашлось.
- **Пробелы не достраиваются.** Если чего-то о вашем бизнесе агент не знает — это `[УТОЧНИТЬ]` в самом документе, не заполненное правдоподобной догадкой.

## Когда не подходит

- Юридическое оформление компании (регистрация, cap table, форма собственности) — не покрыто вообще, это отдельная область, которую даже рыночные лидеры решают плохо (см. `DECISIONS.md`, 2026-08-17).
- Координация живых специалистов (юрист, бухгалтер, маркетолог-человек) — v1 работает только с AI-агентами.
- Живые бизнес-операции (реальные платежи, CRM, банк) — агент не подключён ни к чему подобному, работает только с файлами и текстовыми брифами.

## Чего агент никогда не делает

- Не принимает решение вместо владельца — только предлагает и показывает основания.
- Не выдаёт предположение о рынке/конкурентах/цифрах за проверенный факт.
- Не ставит задачи живым людям от имени владельца.

## Обслуживание

Обновление — см. `UPDATE.md` (`bash update.sh` для служебной части, `installer` для отдельных Skills). Личные файлы (`PROFILE.md`, `MEMORY.md`, `memory/`, `knowledge/`) не трогаются никогда ни при каком обновлении.

## Техническая структура репозитория

```
HOME.md              — устав: кто агент, как начинает задачу, правила
SOUL.md               — характер
PROFILE.md            — кто владелец, какой у него бизнес
MEMORY.md             — постоянные факты (индекс на memory/feedback_*.md)
memory/               — дневник по дням + правки владельца
knowledge/
  businesses/          — накопленный разбор по каждому делу владельца
  evidence/, cases/     — сырой материал, если появится своё исследование
skills/
  business-teardown/    — ядро-способность: intake → teardown → структура
workspace/            — дословно зафиксированные задачи + результаты по ходу
DECISIONS.md          — история решений (Proposal → Discussion → Locked)
OPEN_QUESTIONS.md     — что ещё не выяснено
ROUTING.md            — куда что читать под задачу
```

Обычный markdown — любой файл можно открыть и прочитать напрямую.
